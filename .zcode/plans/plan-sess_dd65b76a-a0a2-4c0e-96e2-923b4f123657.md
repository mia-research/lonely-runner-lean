# Settle the C pooled-tilt lead — calibrated permutation pooled p-value + OOS

## The question (queue item C, the one wall Weil doesn't close)
Is the `inv`-map pooled negative bias (`T_inv`, the orbit-level CDH/inversion statistic) a **real small effect** (~`T_inv` ≈ −0.02, below the ~0.5 per-prime detection floor) or the **tail of noise**? v1 found a sub-detection tilt: 15/18 primes negative, Stouffer z = −2.64, surviving a calibration control — but v1's pooled number rests on **z-inflation correction** (deflate by the 0.793 calibration std), which the record explicitly flags as the wrong tool. The agreed next step: ~30–50 large primes + a **calibrated permutation pooled p-value** + OOS.

## The one methodological fix (the heart of this)
Replace z-deflation with an **empirical null for the pooled statistic itself**. Per prime p:
- exact `T_inv` (orbit-level mean product, `c` constant on μ₃-orbits — the GLV reduction);
- within-prime null = orbit-label permutation, R draws (shares the forced μ₃-orbit symmetry);
- z_p = (T_data − μ_p)/σ_p (float, ranked vs null — `# noqa: float`).

Then build the pooled null directly: draw **one** within-prime null index per prime, combine via Stouffer, repeat B times ⇒ empirical distribution of `Z_pool = Σ z_p/√NP` under the global null. The **calibrated one-sided (left) pooled p-value = #{Z_pool^null ≤ Z_pool^data}/B** — an exact integer count, with the per-prime under-dispersion built in (no deflation fudge). This is the object the record says is missing; a grep for `perm_pool`/`calibrated.*pooled` confirms it does not yet exist.

Stouffer is the primary combiner because the lead is a *consistent mean shift* (not a sparse strong effect — that would call for Fisher/min-P; reported as a sensitivity check only, never as a decision rule, per the counter-prior's "don't manufacture positives").
